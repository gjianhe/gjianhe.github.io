# FreeRTOS-版本号命名规则

FreeRTOS 的版本号命名规则自2017年起采用了基于年份的语义化版本 (Calendar Versioning, CalVer) 系统，取代了之前的主版本号.次版本号.修订号 (x.y.z) 系统。

**当前规则 (CalVer 规则，2017年至今)：**

版本号格式为：**`YYMM.N`**

- **`YYMM`(主版本号):** 代表发布的年份和月份。
    
    - `YY`: 年份的后两位数字。
        
    - `MM`: 月份（两位数字）。
        
    - 例如：`2101`表示 2021 年 1 月发布的版本分支。
        
    
- **`.N`(修订号):** 代表该发布分支下的修订（递增数字）。
    
    - 通常从 `.0`开始，每次对同一年月分支的更新（如功能增强、问题修复）会使修订号递增。
        
    - 例如：`2101.0`是该分支的首个版本，修复后可能变为 `2101.1`。
        
    

**特点：**

1. **可预测性:** 版本号直接反映了发布的时间，方便用户了解版本的新旧。
    
2. **分支稳定:** 同一个 `YYMM`分支下的更新（修订号递增）**保证向后兼容**，不会引入破坏性更改。
    
3. **重大变更:** 如果引入了不兼容的 API 更改或重大架构调整，会通过开启一个新的 `YYMM`分支（即新的年月版本）来发布。
    

**示例：**

- **FreeRTOS V202111.00:** 表示这是 2021 年 11 月创建的发布分支的第一个正式版本。
    
- **FreeRTOS V202112.01:** 表示这是 2021 年 12 月创建的分支的第二个修订版本。
    

**历史规则 (LTS 之前)：**

在采用 CalVer 之前，FreeRTOS 使用经典的 **`x.y.z`** 格式：

- **主版本号 (x):** 重大更新，可能包含不兼容的更改。
    
- **次版本号 (y):** 引入新功能，但保持向后兼容。
    
- **修订号 (z):** 问题修复和安全补丁。
    

**重要提示：**

- **LTS (长期支持) 版本:** 自 V202012.00 起，FreeRTOS 引入了 LTS 版本。LTS 版本会获得长期的支持和维护更新，其版本号依然遵循 `YYMM.N`格式（例如，第一个 LTS 版本是 `V202012.00`）。
    
- **在代码中，** 版本信息通常通过 `FREERTOS_KERNEL_VERSION`等宏定义来标识。
    

**总结：** 现在查看 FreeRTOS 版本，最直接的方式是看其 `YYMM.N`格式的数字，它能清晰指示发布年月和修订情况。
